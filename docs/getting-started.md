# Getting Started

Storing information efficiently (in both the way you store AND retrieve it) is one of the hardest challenges to "solve" in any informative context, and there isn't just one single solution. 

This concept is subject to subjectiveness on every level except the truth you wish to store.

RES doesn't pretend to be the one solution, it just gives every game the same shape so that anyone who has used one RES project can find their way around another, and so that nobody spends a week rediscovering something that was already figured out.

# Starting Out

1. Check `meta.md` for the game, platform, versions, and tools this project covers. Every claim in the project is only as good as the version it was verified on, so keep it up to date.
2. Delete the `example-` file in each folder once you've written your first real page of that type. They exist to show the structure, not to stay.

Read [layout](layout.md) before writing anything so you know where a page belongs, and [standards](standards.md) so it reads like everything else in the project.

# Contributing

**Search before you dig.** The entire point of the project is that finding something already documented is cheaper than finding it again, so check the existing pages and the `5-todos` folder for the same topic first.

**Write down what you don't know.** If you hit something you can't explain yet, make a todo for it instead of leaving it in your head or guessing in a real page. A dead end is worth documenting too, since it saves the next person from trying the same thing.

**Write as you go.** A page written while you're still looking at the answer is almost always better than one reconstructed a month later, and a short accurate page beats a long one that never gets finished.
